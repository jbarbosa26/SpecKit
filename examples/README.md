# BookNook — Example SDD Artifacts

These are **illustrative** Spec-Driven Development artifacts for the *BookNook* personal reading-list / home library web app used throughout the [hands-on walkthrough](../docs/03-walkthrough-and-lab.md). They show what the Spec Kit `/speckit.*` commands would produce for the **Library & Reading Status** feature (`001-library-reading-status`), so you can compare your own output to a known-good result.

| Artifact | Description | Generated by |
| --- | --- | --- |
| [`constitution.md`](./constitution.md) | The five governing principles plus constraints, workflow, and governance | `/speckit.constitution` |
| [`spec.md`](./spec.md) | The feature specification — user stories, requirements, entities, success criteria (WHAT/WHY) | `/speckit.specify` |
| [`plan.md`](./plan.md) | The implementation plan — tech stack, structure, constitution check (HOW) | `/speckit.plan` |
| [`tasks.md`](./tasks.md) | Executable, test-first tasks organized by user story with `[P]` markers | `/speckit.tasks` |

## How to read these

Read them in the order the workflow produces them — it mirrors how intent flows into working software:

1. **`constitution.md`** sets the non-negotiable principles every later artifact must respect.
2. **`spec.md`** captures *what* BookNook does and *why*, with **no technology choices** — note the `[NEEDS CLARIFICATION]` marker that models the methodology.
3. **`plan.md`** introduces the *how* (TypeScript, Vite, Express, SQLite via better-sqlite3, Vitest) and checks the design against the constitution.
4. **`tasks.md`** turns the plan into executable, test-first work, grouped **by user story** so each story ships independently. `[P]` marks parallel-safe tasks.

The four files are intentionally consistent: the functional requirements, entities (Book, Shelf, ReadingStatus), and stack in the spec and plan are exactly the ones the tasks implement.

> These files are **reference outputs only** — this is not a buildable application. In a real project, Spec Kit writes the constitution to `.specify/memory/constitution.md` and the spec/plan/tasks (plus `research.md`, `data-model.md`, `contracts/`, and `quickstart.md`) under `specs/<feature>/`. The numbered `specs/NNN-name/` directory is **always** created; a matching feature branch is added by Spec Kit's git integration when git is available and enabled.
